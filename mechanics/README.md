# LOX — механика замка

`lock-mechanics.mjs` — ES-модуль без зависимостей. Включает генератор, связанные движения, проверку упоров и сессию с поломкой отмычки. Это общий модуль: его использует и интерфейс игры.

## Быстрое подключение

```js
import { createSession, attempt, replacePick } from './lock-mechanics.mjs';

let session = createSession(4, 12345, true);
const result = attempt(session, 0, -1); // первая пластина влево
session = result.state;

console.log(result.event, result.blocked, session.pins);
if (result.event === 'break') session = replacePick(session);
```

В Node.js импорт такой же. Для браузера используйте `<script type="module">`. Если хостинг не обслуживает `.mjs` как JavaScript, переименуйте файл в `.js` и измените импорт.

## Координаты

- Пластины нумеруются с 0; количество: 4–7.
- `pins[i]`: индекс отверстия под неподвижным штифтом, от 0 до 6; центр — 3.
- Направление пластины: `-1` влево, `1` вправо.
- Пластина влево: индекс отверстия под штифтом увеличивается.
- `links[from][to]`: `1` вместе, `-1` навстречу, `0` нет связи.
- Связи направленные, прямые, без цепного распространения.
- При упоре одного затронутого штифта блокируется весь ход.

Для отрисовки с неподвижным штифтом смещение пластины равно `(3 - pins[i]) * шаг_между_отверстиями`. Новое положение сохраняется, а не возвращается после анимации.

## Функции

- `generate(count, seed)` — решаемый замок: `links`, `start`, `pins`, `count`, `seed`, `proof`.
- `move(pins, links, plate, direction)` — новые позиции или `null` при упоре; исходные позиции не изменяет.
- `blockers(pins, links, plate, direction)` — индексы блокирующих пластин. Принимает корректные индексы и направление.
- `solved(pins)` — все штифты в центральных отверстиях.
- `createSession(count, seed, breakPicks)` — сессия с прочностью, ошибками и историей. По умолчанию 4 пластины, seed из времени, поломки включены. Поля `seed` и `proof` в сессию не включаются.
- `attempt(state, plate, direction)` — `{state, event, blocked}`. Передавайте возвращённый `state` в следующий вызов.
- `replacePick(state)` — новая отмычка; замок в исходном положении, история очищена.
- `resetSession(state)` — сброс замка, прочности, ошибок и истории.
- `undo(state)` — отмена успешного хода; ошибки и повреждение не отменяет, со сломанной отмычкой недоступна.

События `attempt`: `move`, `open`, `blocked`, `break`, `broken` (попытка со сломанной отмычкой), `invalid` (неверный индекс или направление).

Первый упор повреждает отмычку, второй ломает и сразу возвращает замок к началу. До замены движение запрещено. При `breakPicks: false` ошибки только считаются. Навыки обученного взломщика и мастера не моделируются.

Генератор перемешивает открытый замок обратимыми допустимыми ходами. `proof` содержит один обратный путь; он не обязательно кратчайший. Одинаковый seed создаёт одинаковый замок. Генератор не является криптографическим.

## Использование как CAPTCHA

Этот модуль — головоломка, а не готовая защита от ботов. Зная позиции и связи, программу решения можно написать без распознавания изображения. Проверка `solved()` в браузере также легко обходится. Поэтому одна такая задача не доказывает, что посетитель человек.

Если использовать её как дополнительную проверку:

1. Генерируйте задачу на сервере. Клиенту передавайте только публичное состояние и случайный идентификатор. Не передавайте `proof` и seed.
2. Храните начальные позиции, связи, срок действия и привязку к сессии на сервере.
3. Принимайте ограниченный по длине список ходов, проверяйте типы и диапазоны и воспроизводите их на сервере через `attempt`. Не доверяйте итоговым позициям или флагу успеха от клиента.
4. После успеха выдавайте одноразовый результат, привязанный к конкретному действию; защищайте от повторного использования и ограничивайте частоту попыток.
5. Предусмотрите доступный альтернативный способ прохождения.

Серверной CAPTCHA, токенов и защиты от автоматического решения в этих файлах нет. Если нужна серьёзная защита, используйте специализированный антибот-сервис вместе с серверными ограничениями.
